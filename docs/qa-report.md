# 产品级重构与 QA 报告

## 审计结论

旧版存在中文编码损坏、场景数据与界面逻辑脱节、状态变量未完整参与剧情、部分按钮没有真实后果、地图与决策弱关联等问题。本次修复保留现有入口与 UI 框架，重写了 `data/scenarios.js` 与 `js/app.js`，并清理了混杂乱码。

## 当前剧情结构

- 15 个真实节点：预警、大厅、食堂、广播、十字路口、校门、网络、错误信息、路线重规划、地下通道、家人协调、停电、原地避险、信息取舍、复盘。
- 每个节点 3 个选择；选项至少修改时间、风险、信息、电量、同伴、物资或路线中的一项。
- 地铁路线会在中段改变节点推进；高风险会触发重新转移；路线状态会改变地图可见性；结局评分综合多个变量。

## 状态参与关系

|状态|实际影响|
|---|---|
|time|倒计时、选择代价、路线窗口|
|risk|积水透明度、地图路线、跳转和复盘评分|
|info|后续情境提示、复盘信息分项|
|battery|资源选择与复盘资源分项|
|network|信息场景显示与后续信息可信度|
|mobility|界面状态显示与可扩展行动约束|
|companion|NPC 协作结果和复盘协同分项|
|supplies|应急包选择和复盘资源分项|
|route|高地、宿舍、地铁路线可视状态及节点跳转|
|stress|随风险累积并参与最终评分|

## 回归测试

1. 官方核实 → 信息上升、电量下降、后续提示改变。
2. 忽略预警 → 风险上升、后续积水提示提前出现。
3. 选择地铁 → 路线状态改变，并在广播节点后跳转到校门场景。
4. 选择宿舍 → 宿舍路线显示，后续网络场景承接。
5. 帮助同伴 → 同伴状态和最终协同评分改变。
6. 刷新信息 → 电量和网络状态恶化。
7. 拒绝短视频 → 信息可信度上升、风险降低。
8. 抄近路 → 风险上升，后续可能触发二次转移。
9. 手电选择 → 电量下降、风险与同伴协作改变。
10. 原地清点物资 → 物资与风险同时改变。

## 已知限制

当前项目的场景底图仍是程序化 UI/地图，不是摄影图片；这是现有离线项目的明确边界。未伪造外部图片来源，也未加入不存在的音频接口。浏览器打开 `index.html` 即可运行，Node.js 语法检查已通过。
